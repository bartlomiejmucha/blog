7. Implementing Qwen3

Write the whole Qwen3 decoder in about 150 lines: grouped-query attention with QK-norm and rotary positions, a SwiGLU MLP, pre-norm residual blocks, and a tied output head.

  • Explain QK-norm and rotary position embeddings at the level the code needs
  • Assemble blocks into a full model with a tied output projection

The shape of the model

Qwen3-0.6B, which Lessons 7 to 10 use, has this structure:

token ids [B, L]
  → embed_tokens                 [B, L, 1024]
  → 28 × TransformerBlock:
        h = x + Attention(RMSNorm(x))
        x = h + MLP(RMSNorm(h))
  → RMSNorm
  → embed_tokens.asLinear        [B, L, 151936]   (tied output head)
→ logits

Every block has the same code and different weights. Writing the model therefore means writing four small modules: attention, the MLP, the block that wires them with residual connections, and the outer model.

Attention

code/Sources/Inference/Qwen3.swiftswift
final class Attention: Module {
    let heads: Int
    let kvHeads: Int
    let headDim: Int
    let scale: Float
    let ropeTheta: Float

    @ModuleInfo(key: "q_proj") var qProj: Linear
    @ModuleInfo(key: "k_proj") var kProj: Linear
    @ModuleInfo(key: "v_proj") var vProj: Linear
    @ModuleInfo(key: "o_proj") var oProj: Linear
    @ModuleInfo(key: "q_norm") var qNorm: RMSNorm
    @ModuleInfo(key: "k_norm") var kNorm: RMSNorm

    init(_ c: Qwen3Config) {
        heads = c.numAttentionHeads
        kvHeads = c.numKeyValueHeads
        headDim = c.headDim
        scale = 1 / Float(c.headDim).squareRoot()
        ropeTheta = c.ropeTheta
        _qProj.wrappedValue = Linear(c.hiddenSize, heads * headDim, bias: false)
        _kProj.wrappedValue = Linear(c.hiddenSize, kvHeads * headDim, bias: false)
        _vProj.wrappedValue = Linear(c.hiddenSize, kvHeads * headDim, bias: false)
        _oProj.wrappedValue = Linear(heads * headDim, c.hiddenSize, bias: false)
        _qNorm.wrappedValue = RMSNorm(dimensions: headDim, eps: c.rmsNormEps)
        _kNorm.wrappedValue = RMSNorm(dimensions: headDim, eps: c.rmsNormEps)
    }

    func callAsFunction(_ x: MLXArray, cache: LayerCache?) -> MLXArray {
        let (B, L) = (x.dim(0), x.dim(1))

        // [B, L, hidden] -> [B, heads, L, headDim]
        let q = qNorm(qProj(x).reshaped(B, L, heads, headDim)).transposed(0, 2, 1, 3)
        let k = kNorm(kProj(x).reshaped(B, L, kvHeads, headDim)).transposed(0, 2, 1, 3)
        let v = vProj(x).reshaped(B, L, kvHeads, headDim).transposed(0, 2, 1, 3)

        let out = attend(q: q, k: k, v: v, cache: cache, scale: scale) { [headDim, ropeTheta] x, offset in
            MLXFast.RoPE(x, dimensions: headDim, traditional: false, base: ropeTheta, scale: 1, offset: offset)
        }
        return oProj(out.transposed(0, 2, 1, 3).reshaped(B, L, heads * headDim))
    }
}

Follow the shapes for a batch of one, L tokens:

  1. Project. q_proj maps 1024 to 16 heads × 128 = 2048; k_proj and v_proj map to 8 heads × 128 = 1024. Reshape to [1, L, heads, 128] and transpose to [1, heads, L, 128], the layout the attention kernel wants.
  2. QK-norm. Each query and key vector is RMS-normalized with its own learned scale. This is new in Qwen3: it keeps attention scores in a stable range, which lets the model train at large learning rates without spikes. For us it is just one more RMSNorm over the last dimension, applied before RoPE.
  3. Rotary positions. RoPE rotates each pair of dimensions by an angle proportional to the token's position, at a different frequency per pair (base rope_theta = 1,000,000). The dot product of a rotated query and key then depends on the distance between them, which is how attention knows word order.
  4. Attend to everything cached so far, plus these tokens.
  5. Merge heads back to [1, L, 2048] and project to 1024 with o_proj.

Steps 3 and 4 live in a small helper, attend, shared by both model families, because the cache logic is the same for all of them:

code/Sources/Inference/LayerCache.swiftswift
let kv = cache as? KVCache
let offset = kv?.offset ?? 0
var (keys, values) = (rope(k, offset), v)
if let kv {
    (keys, values) = kv.update(keys: keys, values: values)
}
return MLXFast.scaledDotProductAttention(
    queries: rope(q, offset), keys: keys, values: values, scale: scale, mask: mask)

(The helper's first branch handles batches of independent sequences, Lesson 15.) The offset is the number of tokens already in the cache: during prefill it is 0, and when decoding token 600 it is 599, so that token is rotated to the right position. The mask is .causal when several tokens arrive at once, so token i cannot see tokens after it; a single decode token may see everything, so no mask is needed.

Grouped-query attention

There are 16 query heads but only 8 key/value heads. Each pair of query heads shares one key/value head. This is grouped-query attention (GQA), and its purpose is the cache: keys and values are what must be stored for every past token, so halving the KV heads halves the cache with little loss in quality. Larger Qwen3 models go further; the 32B model has 64 query heads and 8 KV heads.

The fused attention kernel handles the grouping itself when the number of query heads is a multiple of the KV heads, so the code never copies keys to match queries. Lesson 9 turns this into concrete megabytes.

MLP and block

/// `silu(gate) * x` fused into one kernel, so the product is rounded to
/// bf16 once instead of twice. This matches the Python reference exactly.
let swiglu = compile(shapeless: true) { (gate: MLXArray, x: MLXArray) in

}

final class MLP: Module, UnaryLayer {
    @ModuleInfo(key: "gate_proj") var gateProj: Linear
    @ModuleInfo(key: "up_proj") var upProj: Linear
    @ModuleInfo(key: "down_proj") var downProj: Linear

    init(_ c: Qwen3Config) {
        _gateProj.wrappedValue = Linear(c.hiddenSize, c.intermediateSize, bias: false)
        _upProj.wrappedValue = Linear(c.hiddenSize, c.intermediateSize, bias: false)
        _downProj.wrappedValue = Linear(c.intermediateSize, c.hiddenSize, bias: false)
    }

    func callAsFunction(_ x: MLXArray) -> MLXArray {
        downProj(swiglu(gateProj(x), upProj(x)))
    }
}

SwiGLU uses two input projections: one is passed through SiLU and acts as a gate on the other, elementwise. Then down_proj maps the 3072-wide result back to 1024. The gate-times-value product is compiled into one kernel, as Lesson 4 described.

code/Sources/Inference/Qwen3.swiftswift
final class TransformerBlock: Module {
    @ModuleInfo(key: "self_attn") var attention: Attention
    @ModuleInfo(key: "mlp") var mlp: UnaryLayer
    @ModuleInfo(key: "input_layernorm") var inputNorm: RMSNorm
    @ModuleInfo(key: "post_attention_layernorm") var postAttentionNorm: RMSNorm

    init(_ c: Qwen3Config, index: Int) {
        _attention.wrappedValue = Attention(c)
        if c.isMoELayer(index) {
            _mlp.wrappedValue = SparseMoE(
                hidden: c.hiddenSize, intermediate: c.moeIntermediateSize!, experts: c.numExperts!,
                topK: c.numExpertsPerTok!, normalizeTopK: c.normTopkProb ?? true, sharedIntermediate: nil)
        } else {
            _mlp.wrappedValue = MLP(c)
        }
        _inputNorm.wrappedValue = RMSNorm(dimensions: c.hiddenSize, eps: c.rmsNormEps)
        _postAttentionNorm.wrappedValue = RMSNorm(dimensions: c.hiddenSize, eps: c.rmsNormEps)
    }

    func callAsFunction(_ x: MLXArray, cache: LayerCache?) -> MLXArray {
        let h = x + attention(inputNorm(x), cache: cache)
        return h + mlp(postAttentionNorm(h))
    }
}

The block is pre-norm: each sublayer sees a normalized input, and its output is added to the residual stream rather than replacing it. The stream itself is never normalized inside the stack, which is why its values can grow large; in Qwen3-0.6B some reach about 8,000 by layer 2. Keep that in mind for the next lesson, because bfloat16 at 8,000 has a step size of 32.

The mlp property is typed UnaryLayer so that mixture-of-experts layers can take its place (Lesson 16).

The full model

code/Sources/Inference/Qwen3.swiftswift
final class Qwen3Backbone: Module {
    @ModuleInfo(key: "embed_tokens") var embedTokens: Embedding
    @ModuleInfo(key: "layers") var layers: [TransformerBlock]
    @ModuleInfo(key: "norm") var norm: RMSNorm

    init(_ c: Qwen3Config) {
        _embedTokens.wrappedValue = Embedding(embeddingCount: c.vocabSize, dimensions: c.hiddenSize)
        _layers.wrappedValue = (0 ..< c.numHiddenLayers).map { TransformerBlock(c, index: $0) }
        _norm.wrappedValue = RMSNorm(dimensions: c.hiddenSize, eps: c.rmsNormEps)
    }

    func callAsFunction(_ tokens: MLXArray, caches: [LayerCache]?) -> MLXArray {
        var h = embedTokens(tokens)
        for (i, layer) in layers.enumerated() {
            h = layer(h, cache: caches?[i])
        }
        return norm(h)
    }
}
code/Sources/Inference/Qwen3.swiftswift
/// Qwen3 decoder, dense or mixture-of-experts. Maps token ids `[B, L]` to logits `[B, L, vocab]`.
public final class Qwen3Model: Module, LanguageModel {
    public let config: Qwen3Config
    @ModuleInfo(key: "model") var model: Qwen3Backbone
    @ModuleInfo(key: "lm_head") var lmHead: Linear?

    public init(_ config: Qwen3Config) {
        self.config = config
        _model.wrappedValue = Qwen3Backbone(config)
        if !config.tieWordEmbeddings {
            _lmHead.wrappedValue = Linear(config.hiddenSize, config.vocabSize, bias: false)
        }
    }

    public func callAsFunction(_ tokens: MLXArray, caches: [LayerCache]?) -> MLXArray {
        let h = model(tokens, caches: caches)
        // Tied models reuse the embedding matrix as the output projection.
        return lmHead?(h) ?? model.embedTokens.asLinear(h)
    }

    public func makeCaches() -> [LayerCache] {
        (0 ..< config.numHiddenLayers).map { _ in KVCache() }
    }
}

The outer key "model" reproduces the checkpoint's model. prefix. lm_head is optional: for tied models the property stays nil, so the parameter tree has no lm_head.weight, which is exactly what verify: [.all] expects. makeCaches returns one empty cache per layer; Lesson 9 fills them.

The model conforms to a two-method protocol that the rest of the server programs against, so the generation loop and engines work for Qwen3 and Qwen3.5 alike:

/// What the generation loop needs from a model.
public protocol LanguageModel: AnyObject {
    /// Token ids `[B, L]` to logits `[B, L, vocab]`, updating `caches`.
    func callAsFunction(_ tokens: MLXArray, caches: [LayerCache]?) -> MLXArray
    /// One fresh cache per layer.
    func makeCaches() -> [LayerCache]
}

Lesson in one breath

Qwen3 is a stack of identical pre-norm blocks: x + attention(norm(x)), then h + mlp(norm(h)). Attention projects to 16 query heads and 8 shared key/value heads, normalizes queries and keys per head, rotates them by position, and runs fused causal attention against the cache. The MLP is SwiGLU. A final norm and the tied embedding matrix turn the last hidden state into logits.

Exercise 1compute it

Qwen3-0.6B: hidden size 1024, 16 query heads, head dim 128. What is the output width of q_proj?

16 heads × 128 = 2048. Note it is wider than the hidden size: Qwen3 sets head_dim independently of hidden_size / heads.

Exercise 2one answer

With 16 query heads and 8 KV heads, how does the KV cache compare with full multi-head attention (16 KV heads)?

The cache stores keys and values per KV head. Eight instead of sixteen halves it.

Exercise 3one answer

Decoding the 600th token, what offset does RoPE use?

Positions count from 0. The cache holds 599 tokens (positions 0 to 598), so the new token is at position 599.

Exercise 4one answer

Why is no attention mask needed when decoding a single token?

Causality forbids seeing the future. A lone query is the latest position, so nothing in the keys is in its future.

Exercise 5put in order

Order the steps inside Qwen3 attention.

Project to queries, keys and values
RMS-normalize queries and keys per head
Rotate queries and keys by position (RoPE)
Append keys and values to the cache
Fused causal attention
Merge heads and apply o_proj

QK-norm comes before RoPE in Qwen3; keys are rotated before caching, so cached keys never need rotating again.
