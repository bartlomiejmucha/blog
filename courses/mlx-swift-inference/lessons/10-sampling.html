From logits to a distribution

The model's output for the last position is 151,936 logits. Softmax turns them into probabilities. Before the softmax, divide by a temperature T:

  • T = 1: the model's own distribution.
  • T < 1: differences are magnified, so likely tokens become more likely. Answers get more focused and more repetitive.
  • T > 1: the distribution flattens, so unlikely tokens get a real chance. Answers get more varied and less coherent.
  • T → 0: all mass goes to the top token. That is greedy decoding, which we special-case as a plain argmax.

Temperature alone has a problem: the tail. With 150,000 tokens, even tiny probabilities add up to a noticeable chance of drawing nonsense. The truncation methods cut the tail off before drawing.

Truncation: top-k, top-p, min-p

MethodKeepsBehaviour
top-kthe k most likely tokensFixed size. Too few when many tokens are plausible, too many when one is obvious.
top-p (nucleus)the smallest set of most likely tokens whose total probability reaches pAdapts: a few tokens when the model is confident, many when it is not.
min-ptokens with probability at least p × the top token's probabilityAdapts to confidence directly; cheap, because it needs no sort.

Try them below on a toy distribution. Notice that min-p and top-p both shrink the kept set when the distribution is peaked (low temperature) and grow it when it is flat, while top-k does not care.

/// The distribution the sampler draws from, as log-probabilities: the
/// logits after temperature, top-k, min-p and top-p. Requires
/// temperature > 0.
public func logProbabilities(_ logits: MLXArray) -> MLXArray {
    let p = parameters
    let scaled = logits.asType(.float32) / p.temperature
    var logprobs = scaled - scaled.logSumExp(axis: -1, keepDims: true)
    let masked = MLXArray(-Float.infinity)

    if p.topK > 0 && p.topK < logprobs.dim(-1) {
        // The k-th largest value is the cutoff. argPartition puts it at
        // index vocab-k without fully sorting.
        let kth = takeAlong(logprobs, argPartition(logprobs, kth: -p.topK, axis: -1)[.ellipsis, (-p.topK)...(-p.topK)], axis: -1)
        logprobs = which(logprobs .< kth, masked, logprobs)
    }

    if p.minP > 0 {
        // Keep tokens whose probability is at least minP times the top one.
        let threshold = logprobs.max(axis: -1, keepDims: true) + log(MLXArray(p.minP))
        logprobs = which(logprobs .< threshold, masked, logprobs)
    }

    if p.topP < 1 {
        // Sort descending, keep the smallest prefix whose mass reaches topP.
        let order = argSort(-logprobs, axis: -1)
        let sorted = takeAlong(logprobs, order, axis: -1)
        let cumulative = cumsum(exp(sorted), axis: -1)
        // A token survives if the mass *before* it is still below topP.
        let keep = (cumulative - exp(sorted)) .< p.topP
        let filtered = which(keep, sorted, masked)
        logprobs = putAlong(logprobs, order, values: filtered, axis: -1)
    }

    // Renormalize what survived.
    return logprobs - logprobs.logSumExp(axis: -1, keepDims: true)
}

Everything runs on log-probabilities, on the GPU, without leaving MLX:

  • Temperature scales the logits, and subtracting logSumExp turns them into log-probabilities without overflow.
  • Top-k uses argPartition, which puts the k-th largest element in its sorted position without sorting the whole vocabulary, and masks everything below it to −∞.
  • Min-p is one comparison: in log space, "at least p times the top probability" is "at least max + log p".
  • Top-p needs a sort: sort descending, take the cumulative sum of probabilities, keep each token whose preceding mass is still below p (so the token that crosses p is kept), and scatter the mask back to vocabulary order with putAlong.
  • The survivors are renormalized so they sum to 1 again.

Why return the distribution instead of just a token? Speculative decoding (Lesson 18) must know the exact probability the sampler would give each token, both for the target model and for the drafter. Exposing logProbabilities makes the sampler's distribution a value the rest of the code can reason about.

code/Sources/Inference/Sampler.swiftswift
/// Draws one token from `logprobs` (`[B, vocab]`), using the seeded key
/// if there is one.
public mutating func sample(fromLogProbs logprobs: MLXArray) -> MLXArray {
    if let current = key {
        let parts = MLXRandom.split(key: current)
        key = parts.0
        return MLXRandom.categorical(logprobs, key: parts.1)
    }
    return MLXRandom.categorical(logprobs)
}

categorical draws an index with probability proportional to exp(logprob), and −∞ entries can never be drawn. When a request sets seed, the sampler keeps an explicit random key and splits it before every draw: one half becomes the new key, the other is used once. The sequence of draws then depends only on the seed, not on whatever else used the global random state, so the same request with the same seed returns the same text. Without a seed, MLX's global generator is used.

Two practical notes. Greedy decoding skips all of this and calls argMax, which is both faster and exactly reproducible. And OpenAI's API defaults to temperature 1; the server in this course defaults to 0.7, a common choice for chat with small models.

Lesson in one breath

Temperature divides the logits before the softmax: below 1 sharpens, above 1 flattens, 0 means greedy. Top-k keeps the k best tokens, top-p the smallest set whose probability reaches p, min-p every token at least p times as likely as the best one. All three work on log-probabilities on the GPU, and the result is renormalized before drawing from it. A split random key makes the whole sequence reproducible.

Exercise 4one answer

Why does the top-k code use argPartition instead of argSort?

Partitioning is linear time; a full sort is not, and the order of the kept tokens does not matter.

Exercise 5one answer

Two requests with the same prompt, temperature 0.8 and seed 42 return different text. Which is the likely cause in a server built like this one?

The random draws are reproducible, but they are applied to logits. Any change in how the logits were computed (a different kernel shape, a different cache path) can move a token across a sampling boundary.
