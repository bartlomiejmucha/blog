5. Reading a checkpoint

A Hugging Face model is a folder of JSON and safetensors files. Learn what is in each, how weights are named, and exactly how MLX's 4-bit format stores a matrix.

By the end of this lesson you can

  • Read a model's config.json and know which fields the code needs
  • Explain the safetensors format and why it loads fast
  • Map checkpoint tensor names to modules, including tied embeddings
  • Compute the size and error of MLX affine group quantization
  • Write the Qwen3 config type and weight loader

What is in the folder

Download mlx-community/Qwen3-0.6B-4bit, the small model used through Lesson 10, and list it:

config.json              architecture hyperparameters
model.safetensors        the weights (large models split this into shards)
model.safetensors.index.json   which tensor is in which shard
tokenizer.json           the BPE vocabulary and merge rules
tokenizer_config.json    special tokens and the chat template
vocab.json, merges.txt, added_tokens.json, special_tokens_map.json

Two files define the model: config.json and the safetensors. The tokenizer files are the subject of the next lesson.

Each field becomes a dimension or a constant in the model code: the width of the hidden vector, the number of layers, the MLP's inner width, how many query and key/value heads attention uses, the base frequency of the rotary position encoding, and the vocabulary size. model_type tells the server which implementation to use. quantization appears only in pre-quantized MLX checkpoints.

The Swift side is a Codable struct with only the fields the code uses. convertFromSnakeCase maps num_hidden_layers to numHiddenLayers, so no coding keys are needed:

The real file also has optional mixture-of-experts fields (Lesson 16) and a load(from:) helper that decodes the file with that key strategy.

safetensors

A .safetensors file is deliberately simple:

  1. 8 bytes: the length of the header, as a little-endian integer;
  2. the header: JSON mapping each tensor name to its dtype, shape and byte range;
  3. the raw bytes of every tensor, back to back.
{"model.layers.0.mlp.down_proj.weight": {"dtype": "U32", "shape": [1024, 384],
                                         "data_offsets": [0, 1572864]},
 "model.layers.0.mlp.down_proj.scales": {"dtype": "BF16", "shape": [1024, 48], ...},
 ...}

There is no code in the file, unlike Python pickle-based formats, so loading one cannot execute anything. And because each tensor is a contiguous byte range at a known offset, a loader can map the file into memory and hand the bytes to the GPU directly. MLX.loadArrays(url:) returns a [String: MLXArray] whose arrays are read lazily.

Large models are split into shards (model-00001-of-00004.safetensors, ...) with an index file. Our loader simply reads every .safetensors file in the folder and merges the dictionaries, which works for one file or fifty.

Names and tied embeddings

The tensor names are the module paths from Lesson 4. For Qwen3:

NameShape (bf16 model)What it is
model.embed_tokens.weight[151936, 1024]one vector per token id
model.layers.N.input_layernorm.weight[1024]RMSNorm before attention
model.layers.N.self_attn.{q,k,v,o}_proj.weight[2048, 1024], [1024, 1024], ...attention projections
model.layers.N.self_attn.{q,k}_norm.weight[128]per-head RMSNorm on queries and keys
model.layers.N.mlp.{gate,up,down}_proj.weight[3072, 1024], ...the SwiGLU MLP
model.norm.weight[1024]final RMSNorm

One name is conspicuously missing: lm_head.weight, the output projection from a hidden vector to 151,936 logits. With tie_word_embeddings: true the model reuses the embedding matrix for it, read the other way round: the logit for token t is the dot product of the hidden vector with token t's embedding. That saves 155 million parameters on this small model, a quarter of its total. In MLX, Embedding.asLinear(x) does exactly this multiply, quantized or not.

Affine group quantization

MLX's default quantization is affine, per group. Take a row of the weight matrix and cut it into groups of 64 consecutive values. For each group:

  1. find its minimum and maximum;
  2. set scale = (max − min) / 15 and bias = min, so the 16 integer levels 0..15 span the group's range;
  3. store each weight as q = round((w − bias) / scale), a 4-bit integer.

Reconstruction is w ≈ scale × q + bias. The error per weight is at most half a step, scale / 2, so groups with a narrow range are stored precisely and one outlier only hurts its own group of 64. Try it in the diagram: drag the outlier and watch the step size, and the error of every other weight in the group, grow.

Storage. Each weight costs 4 bits. Each group also stores a bfloat16 scale and bias, 32 bits shared by 64 weights, which is 0.5 bits per weight. So "4-bit" really means 4.5 bits per weight, and 8-bit means 8.5. In the file you see this as three tensors per layer: weight as U32 with 8 values packed per word, so its last dimension is in / 8; and scales and biases with last dimension in / 64.

The loader

code/Sources/Inference/Loader.swiftswift
/// Builds a Qwen3 model from a local Hugging Face directory.
public func loadQwen3(from directory: URL) throws -> Qwen3Model {
    let config = try Qwen3Config.load(from: directory)
    let model = Qwen3Model(config)

    // 1. Read every *.safetensors shard into one flat name -> array map.
    let files = try FileManager.default.contentsOfDirectory(at: directory, includingPropertiesForKeys: nil)
        .filter { $0.pathExtension == "safetensors" }
    guard !files.isEmpty else { throw LoadError.noWeights(directory) }
    var weights = [String: MLXArray]()
    for file in files {
        weights.merge(try loadArrays(url: file)) { _, new in new }
    }

    // Tied models have no separate output projection.
    if config.tieWordEmbeddings { weights["lm_head.weight"] = nil }
    stackExperts(&weights)

    // 2. Swap Linear/Embedding for their quantized versions wherever the
    //    checkpoint ships scales, so the parameter shapes match.
    if let q = config.quantization {
        quantize(model: model) { path, _ in
            weights["\(path).scales"] != nil ? (q.groupSize, q.bits, .affine) : nil
        }
    }

    // 3. Copy the arrays into the module tree. `.all` fails on any missing
    //    or unexpected key, which catches naming mistakes early.
    try model.update(parameters: ModuleParameters.unflattened(weights), verify: [.all])
    eval(model)
    return model
}

Four steps, and the order matters:

  1. Read every shard into one flat dictionary.
  2. Clean up names: drop lm_head.weight for tied models, and stack per-expert tensors for mixture-of-experts models (Lesson 16).
  3. Quantize the module tree first. A fresh model has float Linear layers expecting a [1024, 1024] weight, but the file holds a packed [1024, 128] integer weight plus scales and biases. quantize swaps each layer whose name has a .scales entry in the file for a QuantizedLinear, so the shapes line up.
  4. Update with verification, then eval once so the weights are materialized before the first request instead of during it.

The Qwen3.5 loader in Lesson 17 adds one more trick: it loads an original bfloat16 checkpoint and quantizes it itself, which is how it keeps the MTP head that pre-converted community checkpoints strip out.

Lesson in one breath

A checkpoint folder holds config.json (architecture hyperparameters), tokenizer files, and safetensors shards: a JSON header followed by raw tensor bytes, so loading is little more than mapping the file. Tensor names are module paths. MLX's affine quantization stores each group of 64 weights as 4-bit integers plus a bfloat16 scale and bias, about 4.5 bits per weight.

Exercise 1compute it

MLX 8-bit quantization with group size 64 and bfloat16 scales and biases. How many bits does each weight cost on average?

8 bits for the value, plus 32 bits of scale and bias shared by 64 weights = 0.5. Total 8.5.

Exercise 2compute it

A 4-bit MLX checkpoint has model.embed_tokens.weight with shape [151936, 128] and dtype U32. What is the model's hidden size?

Each UInt32 packs eight 4-bit values, so 128 words hold 1024 weights per row.

Exercise 3one answer

A Qwen3 checkpoint has no lm_head.weight. Where do the logits come from?

With tie_word_embeddings the same matrix maps ids to vectors on the way in and vectors to logits on the way out. Embedding.asLinear does the second direction.

Exercise 4one answer

Why must the loader call quantize(model:) before update(parameters:) for a pre-quantized checkpoint?

QuantizedLinear has weight, scales and biases parameters of different shapes. Swapping first makes the module tree match the file exactly, so verify .all passes.

Exercise 5compute it

A group's weights range from −0.30 to 0.45. With 4-bit affine quantization, what is the largest possible rounding error for a weight in this group? (Give it to three decimals.)

scale = (0.45 − (−0.30)) / 15 = 0.05. Rounding to the nearest level is off by at most half a step: 0.025.
