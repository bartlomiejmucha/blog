19. MTP: Qwen3.5's built-in drafter

Every Qwen3.5 checkpoint ships a one-layer head trained to predict two tokens ahead. Wire it up as the drafter, roll back linear-attention state on rejection, remove the hidden GPU waits, and measure where it pays off.

By the end of this lesson you can

  • Explain what the MTP head computes and what it takes as input
  • Implement the MTP speculative loop: prefill, draft, verify, commit or roll back
  • Roll back Gated DeltaNet state using per-token snapshots from the kernel
  • Structure a step so it synchronizes with the GPU once
  • Interpret the measured speed-ups at 4, 8 and 16 bits

A drafter inside the model

Separate draft models have problems: they must share the tokenizer, they cost memory, and their predictions often differ from the target's. Qwen3.5 avoids all of this. It was trained with a multi-token prediction (MTP) objective: besides predicting token t+1 from position t, a small extra head learned to predict token t+2. That head ships in every checkpoint as 15 tensors under mtp..

code/Sources/Inference/MTPHead.swiftswift
/// Qwen3.5's multi-token-prediction head.
///
/// The main model's hidden state at position t already encodes "what comes
/// after t". Given that state and the embedding of token t+1, this head runs
/// one extra full-attention decoder layer and predicts token t+2. It shares
/// the main model's embedding table and output projection.
public final class MTPHead: Module {
    @ModuleInfo(key: "pre_fc_norm_embedding") var preNormEmbedding: RMSNorm
    @ModuleInfo(key: "pre_fc_norm_hidden") var preNormHidden: RMSNorm
    @ModuleInfo(key: "fc") var fc: Linear
    @ModuleInfo(key: "layers") var layers: [Qwen35Block]
    @ModuleInfo(key: "norm") var norm: RMSNorm

    init(_ c: Qwen35Config) {
        _preNormEmbedding.wrappedValue = RMSNorm(dimensions: c.hiddenSize, eps: c.rmsNormEps)
        _preNormHidden.wrappedValue = RMSNorm(dimensions: c.hiddenSize, eps: c.rmsNormEps)
        _fc.wrappedValue = Linear(2 * c.hiddenSize, c.hiddenSize, bias: false)
        _layers.wrappedValue = (0 ..< (c.mtpNumHiddenLayers ?? 1)).map { _ in Qwen35Block(c, linear: false) }
        _norm.wrappedValue = RMSNorm(dimensions: c.hiddenSize, eps: c.rmsNormEps)
    }

    /// `embeddings` and `hidden` are `[B, L, hidden]`: the embedding of token
    /// t+1 paired with the main model's final hidden state at t. Returns the
    /// head's hidden state, which the shared output projection turns into
    /// logits for token t+2.
    public func callAsFunction(embeddings: MLXArray, hidden: MLXArray, caches: [KVCache]) -> MLXArray {
        var h = fc(concatenated([preNormEmbedding(embeddings), preNormHidden(hidden)], axis: -1))
        for (layer, cache) in zip(layers, caches) {
            h = layer(h, cache: cache)
        }
        return norm(h)
    }

    public func makeCaches() -> [KVCache] {
        layers.map { _ in KVCache() }
    }
}

Its input is a pair for each position t:

  • the main model's final hidden state at t (after the last norm, the same vector the output projection reads), which already encodes what comes next; and
  • the embedding of token t+1, which tells the head which of the possible next tokens actually came.

Both are RMS-normalized, concatenated, projected back to the hidden size by fc, and passed through one full-attention decoder block with its own small KV cache. The main model's output projection turns the result into logits for token t+2. The head reuses the main model's embedding table and output projection, so it adds only one block's worth of weights.

The generator

code/Sources/Inference/MTPGenerator.swiftswift
/// Speculative decoding with Qwen3.5's MTP head as the drafter.
///
/// Every step:
/// 1. The MTP head has already proposed a draft token `d` for the position
///    after `last`.
/// 2. The main model runs on `[last, d]` in one forward pass. Its first
///    output says what should follow `last`; its second says what follows `d`.
/// 3. If the main model agrees with `d`, both `d` and the token after it
///    are emitted: two tokens for one pass. Otherwise only the main model's
///    own choice is emitted, and the caches forget `d`.
/// 4. The MTP head reads the newly committed positions and drafts again.
///
/// With greedy sampling the output is the same as plain greedy decoding.
/// With temperature > 0 drafts are accepted by rejection sampling, which
/// keeps the output distribution the same as the main model's.
public struct MTPGenerator: Sequence, IteratorProtocol {
    let model: Qwen35Model
    let mtp: MTPHead
    public let caches: [LayerCache]
    let mtpCaches: [KVCache]
    var sampler: Sampler
    let maxTokens: Int

    var last: MLXArray            // [1, 1], the newest committed token
    var draft: MLXArray           // [1, 1]
    var draftLogProbs: MLXArray?  // MTP distribution of the draft, when sampling
    var ready: [Int] = []
    public private(set) var generated = 0
    public private(set) var steps = 0
    public private(set) var accepted = 0

    public init(model: Qwen35Model, prompt: [Int], parameters: SamplingParameters, maxTokens: Int) {
        precondition(model.mtp != nil, "load the model with withMTP: true")
        self.model = model
        self.mtp = model.mtp!
        self.caches = model.makeCaches()
        self.mtpCaches = mtp.makeCaches()
        self.sampler = Sampler(parameters)
        self.maxTokens = maxTokens

        // Prefill the main model on the whole prompt, keeping hidden states.
        let promptArray = MLXArray(prompt.map(Int32.init)).reshaped(1, -1)
        let (logits, hidden) = model.forward(promptArray, caches: caches)
        let first = sampler(logits[0..., -1, 0...]).reshaped(1, 1)

        // Prefill the MTP head. Position i pairs hidden[i] with the token at
        // i+1, so the inputs are the prompt shifted left plus the first token.
        let shifted = concatenated([promptArray[0..., 1...], first.asType(.int32)], axis: 1)
        last = first
        ready = [first.item(Int.self)]
        draft = first
        (draft, draftLogProbs) = propose(tokens: shifted, hidden: hidden)
    }

Prefill runs the main model over the prompt, keeping the hidden states, and samples the first token. Then it prefills the MTP head: position i pairs hidden state i with the token at i+1, so the head's token inputs are the prompt shifted left by one, with the first generated token appended. The head's output at the last position is the first draft.

code/Sources/Inference/MTPGenerator.swiftswift
/// Runs the MTP head on newly committed (token, hidden) pairs and drafts
/// the token after the last one.
mutating func propose(tokens: MLXArray, hidden: MLXArray) -> (MLXArray, MLXArray?) {
    let h = mtp(embeddings: model.embed(tokens), hidden: hidden, caches: mtpCaches)
    let logits = model.logits(h[0..., (-1)..., 0...])[0..., 0, 0...]
    if sampler.parameters.temperature == 0 {
        return (argMax(logits, axis: -1).reshaped(1, 1), nil)
    }
    let logprobs = sampler.logProbabilities(logits)
    return (sampler.sample(fromLogProbs: logprobs).reshaped(1, 1), logprobs)
}

A step

code/Sources/Inference/MTPGenerator.swiftswift
mutating func step() {
    steps += 1
    for case let cache as LinearCache in caches { cache.recordSnapshots = true }
    let input = concatenated([last, draft], axis: 1).asType(.int32)
    let (logits, hidden) = model.forward(input, caches: caches)
    for case let cache as LinearCache in caches { cache.recordSnapshots = false }

    // Build the accept decision, the correction and the bonus token as
    // one lazy graph, then read them back with a single GPU sync.
    let (ok, correction) = verify(logits[0..., 0, 0...])
    let bonus = sampler(logits[0..., 1, 0...]).reshaped(1, 1)
    eval(ok, correction, bonus, draft)

    if ok.item(Bool.self) {
        accepted += 1
        // Both positions are committed. The second output is a free extra token.
        ready += [draft.item(Int.self), bonus.item(Int.self)]
        let committed = concatenated([draft, bonus], axis: 1).asType(.int32)
        last = bonus
        (draft, draftLogProbs) = propose(tokens: committed, hidden: hidden)
    } else {
        // Drop the rejected draft from every cache, then commit the fix.
        for cache in caches { cache.trim(1) }
        ready.append(correction.item(Int.self))
        last = correction
        (draft, draftLogProbs) = propose(
            tokens: correction.asType(.int32), hidden: hidden[0..., ..<1, 0...])
    }
}
code/Sources/Inference/MTPGenerator.swiftswift
/// Decides whether the main model accepts the draft, and which token to
/// emit instead if it does not. Both results are lazy arrays.
mutating func verify(_ targetLogits: MLXArray) -> (ok: MLXArray, correction: MLXArray) {
    guard let q = draftLogProbs else {
        let choice = argMax(targetLogits, axis: -1).reshaped(1, 1)
        return (choice .== draft, choice)
    }
    // Accept with probability min(1, p(d) / q(d)).
    let p = sampler.logProbabilities(targetLogits)
    let ratio = exp(takeAlong(p, draft, axis: -1) - takeAlong(q, draft, axis: -1))
    let ok = sampler.uniform([1, 1]) .< ratio
    // On rejection, sample from the leftover mass max(0, p - q).
    let residual = maximum(exp(p) - exp(q), 0)
    let correction = sampler.sample(fromLogProbs: log(residual)).reshaped(1, 1)
    return (ok, correction)
}

Each step runs the target on [last, draft] and then branches:

  • Accepted: emit the draft and the bonus token from position 1. Both positions are now committed, so the MTP head reads both (token, hidden state) pairs and drafts the token after the bonus.
  • Rejected: every cache holds one position too many, the draft's. Trim them all by one, emit the correction, and let the MTP head read the single committed pair.

verify implements Lesson 18's rules: an argmax comparison for greedy decoding, rejection sampling otherwise, both written as lazy array expressions.

Rolling back linear attention

Trimming a KV cache is one integer (Lesson 9). Trimming Gated DeltaNet state is impossible (Lesson 17). So before the verify pass, the generator sets recordSnapshots on every linear cache, and the layer asks the kernel for its history output: the state after each of the two tokens. The convolution window after each token is a slice of the convolution input. On rejection, trim(1) restores the snapshot taken after the first token, last, which is exactly the committed state.

The first version recorded snapshots with the plain-ops recurrence, which keeps per-token states naturally. Measured in a Debug build, that made the 2-token verify pass cost 49 ms against 34 ms for the kernel path, more than the second token itself. Adding the history output to the kernel brought it to 36 ms. In Release the snapshot overhead is about 1 ms on a 17 ms pass.

One sync per step

Lesson 3 warned that every item() makes the CPU wait for the GPU. The first sampled-mode implementation read the acceptance ratio, the draft, the correction and the bonus token with separate item() calls, four waits per step, and it was slower than plain decoding: 30.8 tokens per second against 35.0 (Debug).

The version above builds the accept decision, the correction and the bonus token as one lazy graph and evaluates it once, with eval(ok, correction, bonus, draft), before reading any of them. Sampled-mode throughput rose to 44.3 tokens per second, now faster than plain. Computing a correction or bonus that ends up unused costs a few microseconds of GPU time; each avoided synchronization saves far more.

Results on a base M1

Qwen3.5-0.8B, 256 tokens of a coding answer, Release build:

weights   plain       MTP         speed-up   acceptance   1-token pass   2-token pass
4-bit     92.5 tok/s  87.3 tok/s  0.94×      87%          12.2 ms        16.8 ms
8-bit     50.9 tok/s  66.8 tok/s  1.31×      92%          18.6 ms        18.6 ms
bf16      31.8 tok/s  24.9 tok/s  0.78×      92%          30.1 ms        65.0 ms

The acceptance rate is excellent everywhere: the head agrees with the main model about nine times in ten. What decides the outcome is the last two columns, Lesson 18's c_verify, and they match the kernel measurements from Lesson 15. At 8 bits, two rows cost the same as one, so the second token really is free. At 4 bits, the 2-token pass costs 1.4 normal steps; add about 3 ms for the head (mostly its pass through the 248,000-row output projection) and there is no gain left. In bf16 the multi-row kernel costs 2.2 normal steps.

So on this machine the best configuration for single-user latency is 8-bit weights with MTP: 67 tokens per second at higher precision than 4-bit. Plain 4-bit is faster still but less accurate. On chips with more compute per byte of bandwidth, or on larger models where each step is more firmly bandwidth-bound, the 2-token pass gets cheaper relative to one token, and MTP gains grow. Measure on your hardware with infer <model> bench before choosing.

Checking correctness

Greedy MTP output should equal plain greedy output. For the coding prompt, the two agree for 13 tokens and then diverge. At that point the plain model's top two logits are " Check" 20.375 and " Checks" 20.375, an exact tie in bfloat16, and the 2-token pass's slightly different rounding breaks it the other way. Everything else checks out: acceptance rates near 90% are only possible if the head's inputs (the post-norm hidden state, the shifted tokens, the shared projection) are wired correctly, and a wrong pairing drops acceptance close to zero.

Two things to remember when running MTP in the server: it is used only by the serial engine (batching and speculation compete for the same spare rows in the matmul), and it currently bypasses the prompt cache (Lesson 14).

Lesson in one breath

The MTP head combines the main model's final hidden state at position t with the embedding of token t+1, runs one full-attention block, and predicts token t+2 through the shared output projection. The generator drafts one token per step with it, verifies with a 2-token target pass, and on rejection trims the KV caches and restores linear-attention snapshots that the kernel recorded. On a base M1 the drafter is accepted 84 to 92% of the time; the speed-up is 1.31× at 8 bits, while at 4 bits and bf16 the 2-token pass is too expensive to win.
